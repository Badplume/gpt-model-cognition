# Official pricing updater 3.2.1

The owner-private Site exposes a service writer at `POST /api/pricing` and public-data readback at `GET /api/pricing`. Sites dispatch authenticates the owner or a valid Sites service-access token. No visitor identity is fabricated. These routes only read and write shared public price/FX cache data and never access provider keys, accounts, inference, or connected apps.

Scheduled runs acquire Site service access using the native Sites `get_site` operation and use its short-lived bearer only in `OAI-Sites-Authorization` to this Site's origin. Keep it in memory; never place it in prompts, URLs, logs, Git, or files. POST the writer **without an action** to run the automatic path, then GET readback. The automatic path honors the plugin's persisted enable switch and frequency. `automaticPaused: true` means intentionally disabled, not a source failure. Manual UI updates send `{action:"refresh"}` and may run while automatic updates are off. A successful source has a timestamp and nonzero model count; the FX entry has a dated ECB reference rate. Failures keep the last good data and expose a short sanitized status. Do not retry model inference or redeploy to refresh prices. Routine refreshes require no user session, Key, or account editing.

The existing cloud trigger wakes daily at 09:00 Asia/Shanghai; no duplicate task is needed. The plugin's `pricing_policy` table selects daily or every-three-day refresh and can pause automatic scraping. Next checks align to 09:00 to tolerate scheduler jitter. A five-minute cooldown prevents repeated manual scraping; failed sources may retry after five minutes. Prices and FX over seven days old stop paid execution even when automatic updates are disabled. Weekends use the latest valid ECB working-day rates.

Management is inside the plugin: a dedicated sidebar pricing view (`open_pricing`), native preference controls, quick-settings refresh/status, and model-visible `pricing_status` and `refresh_pricing` tools. Preference mutations require a real signed-in visitor and same-origin website request or the authenticated app-only MCP path. A Site service request cannot change preferences. The service trigger only invokes the already-published updater; parsing, caching, policy and FX calculations belong to the plugin backend.

Pricing sources and parsers are fixed in `lib/pricing.mjs`, `pricing-qwen-deepseek.mjs`, `pricing-glm-kimi.mjs`, and `pricing-global.mjs`. New/changed source schemas must pass fixtures and live source checks before adding coverage. No downloaded JavaScript or MDX is executed. Public fetches have no credentials, reject redirects, and have size/time limits. Never replace missing prices with zero.

Native prices stay CNY or USD per million tokens. Budget, approval ceilings, new call charges and daily reserves use integer micro-CNY. Existing USD settings convert once at the current verified FX rate; the old USD ledger is retained. CNY models use their native rate directly; USD models convert with ECB cross rates. Conservative prices use the highest published tiers/peak rates and automatic cache-write bounds plus a 10% request reserve. Promotions, student benefits and account discounts are excluded from the hard ceiling. Actual invoices can be lower.

An approved request includes price and FX snapshots. If the new conservative ceiling rises, execution requires a fresh plan. An old USD request cannot execute against the CNY budget. No paid inference is needed to maintain or verify this writer.
